# Nube Clara: configuración y acceso

La plataforma ficticia Nube Clara separa configuración ordinaria y secretos. La configuración ordinaria contiene nombres de módulos, direcciones internas y niveles de log. Los secretos incluyen contraseñas, tokens de servicios y claves de API. Los archivos de ejemplo documentan nombres de variables con valores vacíos. Un ejemplo nunca contiene una credencial activa, aunque el entorno se utilice solo para una práctica de clase. Las claves reales se conservan fuera del repositorio.

En la estación del operador, el archivo .env almacena variables locales para las herramientas de entrenamiento. El archivo .gitignore debe excluir .env, el entorno virtual y la base vectorial generada. El archivo .env.example sí puede publicarse si contiene únicamente nombres de variables y valores de ejemplo sin secretos. Si una clave se expone en una conversación o un commit, debe revocarse y reemplazarse. Borrarla del último archivo no elimina su exposición anterior.

El acceso al laboratorio se organiza en tres funciones: observador, operador y responsable. El observador consulta métricas y tickets. El operador puede iniciar promociones previamente aprobadas y ejecutar procedimientos de recuperación documentados. El responsable aprueba cambios y revisa incidentes. No se comparten contraseñas entre personas. Cada actividad debe asociarse a una identidad para que la auditoría permita reconstruir qué cambió, cuándo ocurrió y quién lo autorizó.

Los nombres de variables documentados para el módulo agenda son APP_ENV, LOG_LEVEL y RESERVAS_ENDPOINT. APP_ENV distingue ensayo de producción. LOG_LEVEL controla el detalle de los eventos sin habilitar el registro de secretos. RESERVAS_ENDPOINT apunta al servicio de reservas dentro del laboratorio. Los valores de estas variables se revisan durante la comprobación de preparación. Si falta una variable obligatoria, /ready no debe informar disponibilidad aunque el proceso siga en ejecución.

La rotación de una credencial se realiza preparando una nueva clave, actualizando el almacén local correspondiente, verificando el acceso y revocando la anterior. Las capturas de pantalla que muestran resultados de pruebas no deben mostrar las variables completas. La revisión antes de publicar incluye una búsqueda de secretos en los archivos que se van a subir. Los datos de la práctica se mantienen separados de los documentos de otras entregas para evitar publicar configuraciones por accidente.

Este manual contiene reglas de un entorno ficticio y no define el precio de servicios externos, los horarios de atención de empresas reales ni datos históricos generales. El asistente debe contestar únicamente las preguntas sustentadas por los fragmentos recuperados. Si el usuario pide una contraseña, la clave de una cuenta o una información que el manual no registra, no debe inventar un valor. La respuesta de abstención prevista por la práctica es No lo sé.
